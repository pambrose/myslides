# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Paul Ambrose's personal collection of [kslides](https://github.com/kslides/kslides) presentations — seven topic decks (HTTP, functional programming, Unix, Docker, C, Kotlin DSLs, Redis) plus an index deck that links them. It is a *consumer* of kslides, not a fork of `kslides-template`: the deck sources are the product, and the build exists to generate and serve them. Published to GitHub Pages (<https://pambrose.github.io/myslides>) and Netlify (<https://pambrose-slides.netlify.app>), and deployable to Heroku as an uberjar.

## Build & run

**The primary author workflow is running `fun main()` in `src/main/kotlin/Slides.kt` from IntelliJ (green arrow); `make docs` (`./gradlew run`, from the `application` plugin) does the same from a terminal.** That single run regenerates every deck into `/docs` *and* starts the HTTP server, because `output { }` enables both modes.

The Makefile is a thin wrapper over `./gradlew`:

- `make` (no args) defaults to `help` — a colorized target list generated by `awk` from each target's trailing `##` comment
- `make build` — `./gradlew build -xtest`
- `make build-all` — alias for `stage`; the Gradle `stage` task declares `dependsOn("clean", "shadowJar")`
- `make uberjar` — `./gradlew shadowJar`, producing `build/libs/kslides.jar` with the custom manifest (there is no separate `uberjar` Gradle task)
- `make uber` — build the uberjar and run it (`java -DPORT=$${PORT:-8080} -jar build/libs/kslides.jar $(ARGS)`), matching the `Procfile`
- `make stage` — `./gradlew stage`; this is what Heroku invokes
- `make dist` — `./gradlew installDist`
- `make sync-revealjs` — runs `syncRevealJs` (see Architecture)
- `make docs` — `./gradlew run`: writes every deck into `docs/`, then serves them on 8080 until Ctrl-C. kslides finishes the file output before the server starts, so once 8080 is listening `docs/` is complete. Needs kroki on `localhost:8000` and the three companion repos (see Architecture). Listed in `.PHONY` because a `docs/` directory exists — without it make reports `docs` up to date and does nothing
- `make clean-docs` — `rm -rf docs/playground docs/kroki docs/mermaid`
- `make versions` — `./gradlew dependencyUpdates`; must use `--no-configuration-cache --no-parallel`. Prints only what is behind (plus anything unresolved and a Gradle update), via the `outputFormatter { }` in `configureVersions()`
- `make versions-all` — the same task with `--output-formatter=plain`, the plugin's full report including every up-to-date dependency. 0.66.0 of the ben-manes plugin accepts that flag; 0.60.0 rejected it as an unknown option, so don't pin the plugin back
- `make upgrade-wrapper GRADLE_VERSION=x.y.z` — runs `./gradlew wrapper` twice (Gradle's documented two-pass procedure). With no argument it re-pins the current version, read from `distributionUrl` in `gradle/wrapper/gradle-wrapper.properties` — the only place the Gradle version is kept. Don't reintroduce a `gradle-wrapper` catalog key: Dependabot's wrapper PRs can't update it, and once stale it would make the next `make upgrade-wrapper` downgrade the wrapper.

**There are no tests.** `src/test` does not exist, and `make build` passes `-xtest` accordingly. Don't read a green build as evidence that a deck renders — regenerate and look.

## Architecture

**Two output modes, both on.** `Slides.kt` sets `enableFileSystem = true` (writes static HTML into `/docs` for GitHub Pages / Netlify) and `enableHttp = true` (embedded server, used on Heroku via the uberjar). Every deck is generated both ways from one run.

**One deck per file, all flat at the output root.** `C.kt`, `Docker.kt`, `Dsl.kt`, `Functional.kt`, `Http.kt`, `Redis.kt`, and `Unix.kt` each expose a `fun KSlides.<topic>Presentation()` that `Slides.kt` calls; each sets a root-level `path` (`c.html`, `docker.html`, …). Because no deck is nested, the deck-depth `../` problems that bite `kslides-template` do not arise here — but the site *is* published under a subpath (`/myslides`), so a link or asset path starting with `/` still resolves against the GitHub account root and misses. As of kslides 1.4.0 the library resolves asset paths (logos, corner SVGs, backgrounds, `favicon`, playground/diagram iframes) against the output root itself; corner *links* and paths inside slide content are emitted verbatim and must be written relative.

**Static asset roots differ by output mode, and `/docs` is the single source of truth.** HTTP-served decks read static assets from `src/main/resources/public/`; filesystem-generated decks read them from `/docs`. Rather than commit two copies, `tasks.processResources` copies `docs/images/` to `public/images/` and `docs/favicon.ico` to `public/` in the resources output, so the embedded server serves the exact files the static site does. Neither `src/main/resources/public/images/` nor a second `favicon.ico` exists in the repo — the copies land in `build/resources/main/public/`, never back in `src`. To add an image: drop it under `docs/images/<topic>/` and commit; both delivery paths pick it up on the next build. Anything new that both modes must serve belongs in `/docs` with a matching `from(...)` in `processResources`.

**reveal.js asset sync.** The distribution's single source of truth is the `kslides-core` JAR (at classpath `revealjs/**`); `syncRevealJs` unpacks it into `docs/revealjs/` so the published static decks have working JS/CSS. Two consequences: it is a `Sync` task, so `docs/revealjs/` is made to *match the JAR exactly* and anything hand-added there is deleted on the next run (the local `plugin/copycode/copycode-button-fix.css` added in July 2026 survives only because kslides-core now ships a byte-identical copy); and a core bump may or may not change anything — 1.2.0 brought a newer reveal.js plus `plugin/mermaid/`, while 1.3.0 through 1.5.1 ship it unchanged. Run `make sync-revealjs` after a bump and check `git status` rather than assuming either way. The tree is committed so Pages can serve it without a build step.

**`useLocal` switches playground sources between disk and GitHub.** `Slides.kt` computes `val useLocal = System.getenv("PORT").orEmpty().isEmpty()` and passes it to the C, DSL, and Redis decks. Locally (no `PORT`) their `playground(...)` calls read companion sources from `c-basics/`, `dsl-demo/`, and `redis-demo/`; on Heroku (`PORT` set) they fall back to `githubRawUrl(...)`. **Those three directories are independent git repos, listed in `.gitignore`, and are not checked out by cloning this one** — a local run without them present will reference files that aren't there.

**kroki diagrams need a local container.** `kslidesConfig { krokiUrl = "http://localhost:8000" }`, so diagram slides only regenerate when a kroki server is running there; the rendered output is committed under `docs/kroki/`. Mermaid slides render to `docs/mermaid/`. `make clean-docs` removes all three (`docs/playground`, `docs/kroki`, `docs/mermaid`) — it hard-codes those paths, so extend it whenever a new kind of generated output appears under `docs/`.

**Font sizes are config, not CSS.** kslides exposes them as cascading config values (global → presentation → slide), and `Slides.kt` uses that API rather than hand-written rules:

- `presentationConfig { slideConfig { codeFontSize = "0.60em"; codeWrap = true } }` — code-block size and wrapping for every slide. kslides emits a generated class (`.reveal .kslides-code-N pre`) and stamps it onto each `<section>`, merging with any explicit `classes`. `codeWrap` also pins the highlight plugin's line-number gutter (`.hljs-ln-numbers { white-space: nowrap }`), which a hand-rolled `pre-wrap` rule silently misses — the gutter otherwise breaks two-digit numbers one digit per line.
- `playgroundConfig { fontSize = "20px"; lineHeight = "25px" }` — sizes the Kotlin Playground editor *and* its run-output pane. Absolute units matter: the Playground renders in its own iframe document, so `em` resolves against that document's root, not the slide. `lineHeight` here only pins the spacing these decks have always used; CodeMirror's own ratio already scales with `fontSize`.
- An individual slide overrides either by setting `slideConfig { codeFontSize = … }` on that slide.

**Deck CSS is accumulated with `css += """…"""`** — at the `kslides { }` level for every deck, inside a `presentation { }` for one — and is the right tool only for selectors the config API doesn't expose: `.smallText li` in `C.kt` / `Dsl.kt` / `Redis.kt`, and the inline `style="font-size:30px"` attributes on list items across the decks size *elements within* a slide, which `slideConfig { fontSize }` (whole `<section>`) cannot express. Individual slides opt into a rule with `classes += "name"`, which lands as a class on the generated `<section>`; a two-class selector like `.reveal .big pre` outranks a global `.reveal pre` regardless of declaration order.

**Deployment artifacts already wired in:** `netlify.toml` (publishes `docs/`), `Procfile` + `system.properties` + `app.json` (Heroku, Java 17, `web` dyno runs the uberjar), `.nojekyll` (stops Pages filtering reveal.js's `_*` paths).

## Build configuration

- Kotlin DSL. `build.gradle.kts` is organized as `configureKotlin()` / `configureShadowJar()` / `configureRevealSync()` / `configureVersions()` extension functions called at the top level.
- Version catalog in `gradle/libs.versions.toml` — bump kslides/kotlin/shadow/jvm there, never in `build.gradle.kts`. The `jvm` key drives `jvmToolchain(...)`.
- **Dependabot** (`.github/dependabot.yml`) is the `gradle` ecosystem only, weekly, with a 7-day `cooldown`: the catalog plus the wrapper. `com.kslides:*` is its own group, listed before `gradle-minor-and-patch` so kslides never lands bundled with other bumps. A kslides PR still needs the post-bump steps under Conventions. There are no workflows, so nothing builds Dependabot's PRs, and no `github-actions` ecosystem to configure; add one if a workflow ever lands.
- `group` and `version` live in `gradle.properties`. `version` is *this repo's* version, distinct from the kslides library version in the catalog.
- `mainName` in `build.gradle.kts` (`"SlidesKt"`) selects the HTTP entry point and the uberjar's `Main-Class`.
- `-Xreturn-value-checker=check` is applied to `compileKotlin` only, deliberately — the checker is scoped to production code so a future test source set using a chained-receiver assertion DSL won't produce false positives.
- **`shadowJar` duplicate handling is two-tiered.** The task sets `duplicatesStrategy = DuplicatesStrategy.INCLUDE`, then narrows it back to `EXCLUDE` via `filesNotMatching(listOf("META-INF/services/**", "META-INF/*.kotlin_module"))`. Gradle applies the strategy *before* Shadow's transformers run, so the default `EXCLUDE` reduces `mergeServiceFiles()` and the built-in `KotlinModuleMetadataTransformer` to first-copy-wins — Shadow 9.6.1 emits about eighty warnings saying so. `INCLUDE` alone would leave genuinely duplicated entries for every path no transformer claims, hence the narrowing. Two gotchas when editing this block: `filesNotMatching` actions are **not** tracked as task inputs, so verify with `./gradlew shadowJar --rerun-tasks` rather than a plain `make build`; and Shadow prints `Duplicate entries found in the shadowed JAR` separately from the transformer warnings, so grep for both.
- The `Built-Date` manifest attribute calls `Date()` at *configuration* time, so its value is frozen into the configuration-cache entry rather than sampled per build. A second `./gradlew shadowJar` reports `UP-TO-DATE` and reuses the CC entry, and the stamp in the jar records when that entry was created. Don't read `Built-Date` as the build time.
- Configuration cache is on (`org.gradle.configuration-cache=true`). New tasks must be CC-compatible; ben-manes' `dependencyUpdates` is the known exception and `make versions` opts out for it.
- `settings.gradle.kts` uses `FAIL_ON_PROJECT_REPOS` and resolves from `mavenCentral()` **and `mavenLocal()`** — unlike `kslides-template`, this repo can pick up a locally published kslides snapshot, which is the point when testing an unreleased core against real decks.

## Conventions for edits

- Record anything user-visible or build-affecting in **both** `CHANGELOG.md` (Keep a Changelog, structured per version) and `RELEASE_NOTES.md` (narrative highlights), and bump `version` in `gradle.properties` in the same commit.
- Regenerating `/docs` is a deliberate act with a large diff (~100 files). Keep it in its own commit, or clearly separated, so review of the source change stays readable.
- After a `kslides` bump (by hand or a merged Dependabot PR): regenerate `/docs` (`make docs`), run `make sync-revealjs`, and check `git status` for both.
